приложение и локальные модели, скачивает проверенные CPU-компоненты PaddleOCR, затем
открывает интерфейс. Дальше работает без интернета. Фотографии распознаются
только по кнопке «Распознать документы». [Инструкция](docs/ONEFILE_WINDOWS.md).

**Цифровые удостоверения, 19.10.2026:** исправлена пустая форма при наличии OCR-текста. Отдельный digital-профиль распознаёт FRONT/BACK мобильного скриншота; найденные реквизиты видны до подтверждения принадлежности сторон. На реальной паре оба CPU-движка дают 15/15 точных ключевых реквизитов. Адрес с перекрытым концом района требует проверки. RapidOCR: 8,43 с холодный документ / 4,96 с последующие; Paddle: 29,11 / 19,43 с. [Причина, изменения, точность и benchmark до/после](docs/DIGITAL_ID_FIX.md). Новая автономная сборка — `dist-digital/DocumentExcel`; запуск через `Launch.cmd`.

Ниже сохранены результаты предыдущего CPU-этапа на **пластиковой** карте.

Обновление 19.10.2026: основной движок — **RapidOCR 3.8.1 / ONNX Runtime CPU 1.23.2 / PP-OCRv5**. Локальные модели: mobile detection, кириллица с русским и кыргызским алфавитом, английский для латиницы/MRZ. NVIDIA, CUDA и cuDNN не нужны. В настройках доступны PaddleOCR CPU для сравнения и Tesseract. Автоматического переключения и скачивания при OCR нет. [Сравнение CPU-движков и точность](docs/CPU_BENCHMARK.md).

Исправления актуальности OCR, раздельного ФИО, проверки источников и запроса регистрации описаны в [аудите](docs/OCR_STATE_AUDIT.md). Для пластиковой карты адрес вводится со слов клиента или из документа с пропиской.

На двух контрольных фотографиях финальной поставки RapidOCR CPU: 6,58 с с загрузкой моделей, 3,46 с на последующие новые документы; PaddleOCR CPU в том же сценарии: 25,58 / 15,57 с. Все пять контрольных форм ФИО совпали. Синтетические критичные поля: 39/40 у обоих; одно короткое кириллическое имя требует ручной проверки. Результаты относятся к этому набору и компьютеру. Предыдущий этап: [оптимизация PaddleOCR](docs/PADDLE_PERFORMANCE.md).

Локальное приложение для распознавания фотографий документов, ручной проверки данных и заполнения Excel-договоров. Русский интерфейс Qt, светлая/тёмная темы, несколько фото на клиента, очередь клиентов. Сеть при работе не используется.

Основной движок — RapidOCR CPU, PaddleOCR CPU доступен в настройках.

Прежняя поставка папкой:

Предыдущие сборки сохранены. Tesseract в `tools/tesseract` можно выбрать при запуске из проекта.

Python и проверенные модели включены в CPU-поставку. Целевая ОС — Windows 10/11 x64, нужен Microsoft Visual C++ Redistributable 2015–2022 x64. Проверено на Windows 10; отдельного прогона на Windows 11 не было. Для Tesseract движок и traineddata устанавливаются отдельно.

## Установка из исходников

Для основной CPU-конфигурации используйте Windows x64 и **Python 3.12**:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup_cpu.ps1
.venv-cpu\Scripts\python run.py
```

Установщик один раз загружает три ONNX-модели и проверяет SHA256. Для установки PaddleOCR CPU отдельно:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup_paddle.ps1
Launch-Paddle.cmd
```

При отдельной установке Paddle выберите «PaddleOCR PP-OCRv5 — CPU» в настройках приложения; общий стандартный движок теперь RapidOCR CPU.

Альтернатива без uv:

```powershell
py -3.12 -m venv .venv-paddle
.venv-paddle\Scripts\python -m pip install -e ".[paddle,dev]"
.venv-paddle\Scripts\python scripts/prepare_paddle_models.py models/paddle
.venv-paddle\Scripts\python run.py
```

Интернет нужен только для установки зависимостей и моделей. CPU-поставка содержит `requirements-locked.txt` с фактически установленными версиями.

## Tesseract

Установите Tesseract **5.x** по [официальной инструкции](https://tesseract-ocr.github.io/tessdoc/); Windows-сборка указана на [странице UB Mannheim](https://github.com/UB-Mannheim/tesseract/wiki). Установка `pytesseract` сам движок не устанавливает.

В «Настройки» выбираются executable, папка traineddata, реальные коды языков, PSM, timeout и подготовка изображений. По умолчанию используются `rus+eng`; `kir` добавляется только при наличии совместимой модели. «Диагностика OCR» показывает фактически доступные языки и ошибки запуска. Также можно выполнить `tesseract --list-langs`.

Для [tessdata_best](https://github.com/tesseract-ocr/tessdata_best) используется LSTM `--oem 1`. Скрипт `scripts/setup_tesseract.ps1` устанавливает движок в новую отдельную папку проекта: проверяет подпись либо SHA256 по официальному релизу и загружает `rus`, `eng`, `kir`. Скрипт требует сеть и может запросить системные права; приложение его автоматически не запускает.

На Fedora установите `tesseract`, `tesseract-langpack-rus`, `tesseract-langpack-eng` через dnf. Наличие кыргызского пакета зависит от репозитория; `kir.traineddata` можно установить отдельно. Linux собирается на Linux отдельным артефактом.

## Работа сотрудника

1. На шаге «Загрузка» перетащите обе стороны документа, выберите фотографии/папку или нажмите «Сделать фото». В камере подтвердите лицевую сторону, затем оборотную: после съёмки OCR запускается автоматически. Файлы и камеру можно сочетать. Все фото относятся к текущему клиенту. Для файлов нажмите «Распознать документы»; автозапуск при загрузке можно включить в настройках.
2. Переключайте стороны в списке. Колёсико меняет масштаб, мышь перемещает изображение; есть поворот на 90°, вписывание и повторный OCR выделенного прямоугольника.
3. На шаге «Проверка» исправляйте значения в сгруппированной форме. Рядом указаны статус и источник; иконка показывает поле на фотографии, меню открывает варианты OCR. Кириллица и латиница сохраняются отдельно. Ошибочная дата остаётся видимой для исправления. Ctrl+Z / Ctrl+Shift+Z отменяют и повторяют ручные изменения текущего клиента.

Буквы перед цифрами идентификатора относятся к полю «Тип / серия документа»: синтетическая строка `ID0000001` разделяется на тип `ID` и номер `0000001`. В Excel они записываются отдельно в E19 и G19 по исходному профилю. Полную строку можно ввести в поле номера — форма разделит её; Ctrl+Z отменит оба изменения вместе. При чтении ID как 10/1D приложение отдельно перечитывает область номера на английском. Оно разделяет поля только после буквального чтения ID и совпадения цифрового суффикса. Неоднозначные значения остаются для сверки с фотографией.

В строке органа выдачи цифры после `МКК` относятся к коду подразделения. Синтетический `МКК 000123` разделяется на орган `МКК` и код `000123`, в исходной карте Excel это J19 и K19. Полную строку можно ввести в поле органа выдачи; изменение обоих полей отменяется вместе. Правило ограничено обозначением МКК и не отрезает числа от названий других органов.
4. Если регистрация не найдена, откроется ручная форма. Можно добавить ещё одно фото или явно указать отсутствие адреса в документе. Регистрация и проживание независимы. По умолчанию договор без обязательной регистрации запрещён.
5. Телефоны, инструменты, залог, стоимость и возврат вводятся вручную. Программа не извлекает телефон из случайных чисел паспорта.
6. Нажмите «Проверить и продолжить» после сверки с оригиналом. На шаге «Excel» выберите XLSX и проверьте таблицу «поле / лист / ячейка». Изменение данных, состава фото или профиля сбрасывает подтверждение.
7. В разделе «Фотографии в договоре» проверьте стороны: FRONT → A1:E24, BACK → F1:K24 листа «Пасп Доп Данные». Нажмите «Сохранить Excel», проверьте значения и фотографии, поставьте отметку подтверждения и выберите **новое имя**. На шаге «Готово» доступны файл текущего клиента, его папка и новый клиент.

В окне камеры доступны выбор устройства, живая рамка, полноразмерный снимок, пересъёмка, поворот и автоматическое/ручное кадрирование. Размытие и недостаток света отмечаются предупреждениями. Через меню фото можно переснять одну сторону, заменить файл или поменять стороны местами. В Excel используется подтверждённая обработанная версия; оригинал сохраняется отдельно. Для настоящего договора обе стороны обязательны; исключение выбирается явно для текущего клиента, только если профиль его разрешает. Подробнее: [камера и фотографии](docs/CAMERA_PHOTOS.md).

Поддерживаются цифровые удостоверения и пластиковые ID-карты КР. Тип и стороны определяются по совокупности признаков; тип можно выбрать на загрузке. У пластиковой карты MRZ TD1 проверяется отдельно, а расхождения с печатными значениями показываются для ручного выбора. Кириллица и латиница хранятся раздельно. Место рождения не становится пропиской: после двух сторон без адреса появляется запрос ручной регистрации или отдельного документа. Подробнее: [пластиковая ID-карта и MRZ](docs/KG_PHYSICAL_ID.md).

Для пакетной работы откройте «Очередь», создайте клиентов и распределите фото. «Распознать очередь» обрабатывает их последовательно. После проверки каждого клиента «Сохранить готовые договоры» создаёт отдельные файлы с отдельным предпросмотром. Неполные записи остаются для исправления. Успешно сохранённые записи пропускаются, пока их данные не изменены.

## Excel и mapping

Во вкладке «Excel-шаблоны» выберите XLSX и откройте редактор. Назначьте поле, реальный лист, ведущую ячейку объединения, тип значения и разрешение замены формулы. Профили создаются, импортируются и экспортируются через GUI. Последний применённый профиль становится стандартным. Там же задаются обязательные поля, телефонная схема и разрешение договора без регистрации.

**Настоящий договор `assets/lermontov.xlsx` проверен.** При выборе его структуры приложение автоматически применяет отдельный профиль: объединённый телефон D7, инструменты в строках 20/22/24/26/28, заводские номера в акте приёма. Дополнительные приложения получают связанные акты. Пользовательские изменённые профили автоматически не заменяются. Java-исходник не предоставлен. Встроенный `DEMO-not-a-contract.xlsx` остаётся тестовым примером. Подробная карта: `docs/MAPPING.md`.

Исходник остаётся резервной копией, существующий результат не перезаписывается. Временный XLSX сохраняется в целевой папке, повторно открывается и проверяется; затем готовый файл публикуется атомарной жёсткой ссылкой без замены существующего имени. Нужен локальный NTFS/ext4 или совместимая файловая система. FAT/exFAT и некоторые сетевые/синхронизируемые папки могут отказать; сохраните на локальный диск.

Формулы вычисляет Excel. openpyxl используется для чтения и проверки; запись меняет ячейки внутри исходного ZIP/XLSX без пересохранения объектов через openpyxl. Неизменяемые части пакета копируются побайтно: логотипы, диаграммы, внешние ссылки, стили и прочие листы сохраняются. Внешние ссылки приложение не открывает и не обновляет. OCR-текст остаётся строкой. Макросы, цифровые подписи, ActiveX и встроенные объекты не поддерживаются. Дополнительные страницы с логотипами поддержаны; копирование страниц со сложными связанными объектами блокируется до публикации результата.

## Ограничения и хранение

Предоставленные цифровые и пластиковые удостоверения проверены локально; они не включены в проект, тесты и отчётные снимки. Карточка определяется отдельно от QR. Мелкие символы могут распознаваться неверно: префикс не достраивается по цифровой строке, имена не исправляются словарём. MRZ TD1 использует отдельные области и проверяет четыре контрольные цифры; это не проверка подлинности документа и не подтверждение всех букв имени. Оценки OCR эвристические; сверка человеком обязательна. Неподписанные поля и сложные макеты могут требовать ручного ввода. MRZ TD2/TD3, PDF, XLSM, RapidOCR и зашифрованные черновики не реализованы. В TIFF обрабатывается первая страница.

Данные клиентов живут в памяти до закрытия или очистки. История хранит только время, операцию и результат; её можно удалить. Настройки/журнал: `%LOCALAPPDATA%/DocumentExcel`, на Linux — `~/.local/share/DocumentExcel`; переменная `DOCUMENT_EXCEL_DATA_DIR` меняет каталог. Журнал ротируется, не содержит OCR-текста, ПИН и путей документов. Исходные файлы не перемещаются и не удаляются. Снимки камеры временные, если хранение изображений выключено; при включённом хранении оригинал и производная сохраняются отдельно в папке клиента. Отдельная команда копирования включает обе версии. Постоянные копии и готовые XLSX остаются на диске. Безопасного стирания SSD нет. При аварии ОС во временной папке могут остаться изображения OCR и камеры; ограничьте доступ к ней.
