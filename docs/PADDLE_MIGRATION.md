# PaddleOCR PP-OCRv5 — интеграция 19 октября 2026

Исторический этап миграции. Текущая основная CPU-конфигурация — RapidOCR с
PP-OCRv5 ONNX; Paddle CPU сохранён для сравнения. См. [CPU benchmark](CPU_BENCHMARK.md).

## Установка и автономный запуск

Нужны Windows x64, Python 3.12 и Microsoft Visual C++ Redistributable 2015–2022 x64. Проверены PaddleOCR 3.7.0, PaddlePaddle CPU 3.3.1, PaddleX 3.7.2. Исходное Python 3.14 окружение сохранено для регрессии и Tesseract; оно не используется для Paddle-сборки.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup_paddle.ps1
Launch-Paddle.cmd
```

Интернет используется только отдельным установщиком. Для другой папки окружения/моделей задайте `-RuntimeDirectory` и `-ModelDirectory`. Для запуска исходников можно задать `DOCUMENT_EXCEL_PADDLE_PYTHON` (путь к pythonw.exe) и `DOCUMENT_EXCEL_PADDLE_MODELS`. В GUI есть выбор папки моделей. Не перезапускайте установщик поверх используемого окружения.

Поставка создаётся из установленного Python 3.12 окружения:

```powershell
.venv-paddle\Scripts\python scripts/package_paddle_windows.py --output dist-paddle/DocumentExcel --models models/paddle
```

Копируйте всю папку DocumentExcel. Запуск — `DocumentExcel.cmd`; свой Python, Qt, Paddle и модели находятся рядом. Это переносимый комплект с частным Python runtime, без MSI и замораживания динамических импортов Paddle в EXE. Системный Python и доступ к исходному окружению ему не нужны. CPU — проверенный вариант. Параметр `gpu:0` предусмотрен, но GPU runtime и GPU inference не проверялись.

## Явный выбор моделей и API

При выполнении задания проверены [официальный код PaddleOCR 3.7.0](https://github.com/PaddlePaddle/PaddleOCR/blob/v3.7.0/paddleocr/_pipelines/ocr.py), [документация 3.x](https://www.paddleocr.ai/latest/en/version3.x/pipeline_usage/OCR.html), [мультиязычные модели PP-OCRv5](https://www.paddleocr.ai/latest/en/version3.x/algorithm/PP-OCRv5/PP-OCRv5_multi_languages.html) и версии PyPI. Установка не полагается на меняющийся default последнего PaddleOCR.

* `PP-OCRv5_mobile_det`: детектор CPU.
* `cyrillic_PP-OCRv5_mobile_rec`: кириллица, в том числе русский и кыргызский алфавиты, цифры; основной проход.
* `en_PP-OCRv5_mobile_rec`: латиница, цифровые поля и TD1 MRZ.

Перед инициализацией проверяются manifest, SHA-256 всех девяти файлов, `Global.model_name` каждой модели, русские/кыргызские буквы и английский MRZ-алфавит с `<`. Модели скачивает только `prepare_paddle_models.py` с официального хранилища Paddle. Рабочий процесс получает только локальные пути. Автоматические классификаторы ориентации и unwarping-модули отключены; сетевые соединения в процессе запрещены. Неисправная/отсутствующая модель приводит к понятной ошибке, без скрытого переключения на другой язык/движок.

Используется `PaddleOCR.predict`, массивы `rec_texts`, `rec_scores`, **`rec_polys`**; нефильтрованные `dt_polys` с текстами не смешиваются. Для отдельных строк применяется 3.x `TextRecognition.predict` с явно заданным `model_name`/`model_dir`, а не API `ocr(..., cls=True)` версии 2.x.

## Архитектура и состояние

`ocr_contract.py` задаёт общий протокол и результат: текст, bbox x/y/width/height, confidence 0–1, script, source_image, engine_name, model_version. `ocr_factory.py` выбирает движок. GUI и RecognitionService используют фабрику, включая повторное чтение поля и диагностику. Tesseract сохраняется и выбирается явно. RapidOCR не подключён: он необязателен и не включается в сравнение как будто протестирован.

Paddle загружается в единственном отдельном процессе; его модельные объекты используются повторно. Смена конфигурации освобождает прежний процесс. Кеш из 64 результатов привязан к содержимому и размеру пикселей/режиму, не к имени файла; исходные изображения не кешируются. Отмена и timeout завершают процесс, следующий запуск создаёт новый. Ожидание импорта тоже ограничено timeout. GUI продолжает работать через существующий QRunnable, прогресс и отмену.

Сохранён транзакционный OcrState: UUID запуска, клиент, хэши реальных байтов, сторона, поворот, оригинальная/обработанная версия, область обновления и актуальный run_id. Старый worker не публикует результат после нового запуска или изменения снимков; смена просматриваемой стороны не уничтожает ClientData; ручные значения сохраняются. Дополнительно исправлено наследование диагностических блоков/областей при повторном проходе ранее обработанной стороны.

## Профили, изображения и MRZ

При объединении областей латинский вариант больше не удаляет найденный кириллический компонент имени. Оптически одинаковые коды ABCEHKMOPTX/АВСЕНКМОРТХ нормализуются только в явно кириллическом crop или верхней кириллической строке физического профиля; сырой OCR сохраняется, статус остаётся REVIEW. Неоднозначные Y/S/R/I не заменяются. Нижняя латинская строка и MRZ не транслитерируются; реальные расхождения сохраняются как конфликты.

Переиспользованы KyrgyzPhysicalIDProfile и KyrgyzDigitalIDProfile, классификация стороны/типа, поиск карты, перспективное выравнивание, семантические подписи и отдельные crop полей. Paddle начинает с цвета; лишь при недостаточном извлечении проверяет один подготовленный вариант. Для специальных реквизитов используются оригинальный crop и при необходимости контрастный вариант вместо всех фильтров. Пустые края строки обрезаются только в копии для нейросетевого recognition. Confidence отдельных полей теперь берётся из реального OCR вместо констант 0.9/0.92.

TD1 разбирается существующим независимым ICAO-парсером: структура, контрольные цифры номера, рождения, окончания и composite. Английский recognizer читает выделенные MRZ-строки; парсер не генерирует недостающие реквизиты. MRZ не заменяет кириллическое имя, не создаёт дату выдачи, расхождения остаются конфликтами. Это форматная проверка, не установление подлинности документа.

Камера, две стороны, Drag & Drop, ручной адрес, Excel mappings и сохранение оригиналов остаются в прежнем workflow. На листе «пасп доп данные» FRONT помещается в A1:E24, BACK — F1:K24. Экспорт по-прежнему требует разрешённых/подтверждённых полей и подтверждения данных клиента.

## Повторяемые проверки

```powershell
.venv-paddle\Scripts\python scripts/check_paddle_runtime.py models/paddle --output test-artifacts/paddle-runtime.json
.venv-paddle\Scripts\python scripts/benchmark_ocr.py --models models/paddle --output test-artifacts/paddle-benchmark
.venv-paddle\Scripts\python -m pytest --junitxml=test-artifacts/paddle-regression.xml
```

Benchmark использует одинаковые синтетические пары FRONT/BACK, перспективу, низкий контраст и цифровой screenshot. Отчёт включает точность девяти полей, целиком правильные документы, ошибочные непустые значения без INVALID/CONFLICT, время, RSS родителя и дочерних процессов с шагом 20 мс. Первое время включает загрузку моделей; последующие документы используют тёплый процесс. ФИО сравнивается точно в установленном порядке, номер — с префиксом. Отсутствующий/ошибочный/conflict результат не засчитывается как правильный. Отчёт не содержит распознанных персональных значений.

Для разрешённого реального локального набора можно передать `--manifest` и явный `--authorized-local-documents`. Manifest — массив объектов с `id`, `images` (пути относительно manifest), `expected` (девять полей из benchmark.FIELDS). Изображения не копируются в отчёт. Новые реальные удостоверения в рамках этой миграции не предоставлены и не использовались.

Наличие Ү/Ө/Ң в словаре не гарантирует их правильное распознавание. Синтетическая строка с кыргызскими буквами показала ошибки регистра и смешение визуально похожих латинских/кириллических знаков. Автоматическая словарная подмена имён не выполняется. Нельзя утверждать превосходство Paddle на документах пользователя без разрешённого репрезентативного набора и ручной разметки.
