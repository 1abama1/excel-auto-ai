# Карта из пользовательского задания

Java-исходники отсутствуют. Ниже сохранена исходная карта задания для демонстрационного шаблона. Для предоставленного `assets/lermontov.xlsx` используется отдельный профиль `lermontov-combined`, проверенный по реальным объединениям и заголовкам.

## Предоставленный договор

- 18 исходных листов, 29 изображений, внешняя ссылка на старую надстройку. Они сохраняются; приложение ссылку не обновляет.
- Основные паспортные ячейки Дог. совпадают с картой ниже. D7:I7 объединены, поэтому оба телефона записываются в D7.
- A21 и I21 содержат формулы регистрации. При пустом адресе проживания они остаются формулами; при явно введённом адресе разрешённая замена показана в предпросмотре.
- Инструменты: строки 20, 22, 24, 26, 28. A — номер, B — название, I — количество, N — цена за сутки. J:K содержат дату/время выдачи и не используются под заводской номер.
- Заводские номера: Акт прием!L21:L25. Стоимость покупки: Акт прием!N21 с явным разрешением замены формулы. Акт расч!N20 содержит ссылку на суточную цену; эта формула не заменяется стоимостью покупки.
- Фактический возврат: Пр №1!G20/G21 и аналогичные пары G22/G23, G24/G25, G26/G27, G28/G29. Старое правило L21 предназначено для демонстрационной карты и здесь не применяется.
- Более пяти инструментов: копируются Пр №1, Акт прием и Акт расч с суффиксом страницы. Их формулы перенаправляются на соответствующее новое приложение; логотипы, печать и объединения сохраняются. Залог есть только на первой странице.
- Автовыбор работает только для неизменённого стандартного профиля и проверенной структуры; изменённые пользователем карты сохраняются.
- Профиль `lermontov-combined` версии 3 включает обязательные фотографии: «Пасп Доп Данные»!A1:E24 — FRONT, F1:K24 — BACK. Имена листов сопоставляются без учёта регистра и лишних пробелов. Контейнеры рассчитываются по настоящим ширинам/высотам; используются contain, центрирование и внутренний отступ, без изменения пропорций.
- `photo_sheet`, `photos_required`, `allow_photo_exception` настраиваются в редакторе профиля. Отсутствующий лист не создаётся. Исключение при отсутствии стороны требует отдельной отметки текущего клиента и разрешения профиля; обычный экспорт требует обе стороны. Предыдущая неизменённая встроенная версия 2 мигрирует автоматически; пользовательский профиль сохраняется.

## Исходная демонстрационная карта

Профиль пластиковой карты не меняет Excel-координаты. `passport_type` и `passport_number` остаются отдельными: видимые буквы ID → E19, цифры → G19. `place_of_birth` и латинские формы ФИО не подставляются в регистрацию. M19 получает печатную дату выдачи, а не дату окончания из MRZ. Отсутствие регистрации на карте требует ручного Address либо отдельного документа и не снимает требования договора.

По пять инструментов на страницу. Затем создаются `Пр №1 (2)`, `(3)` и т. д. Залог на дополнительных страницах очищается, неиспользованные разрешённые ячейки строк очищаются. Если таблица и залог не заданы, приложение её не меняет. При заданном залоге без инструментов строки очищаются, что видно в предпросмотре. Старые дополнительные страницы в исходнике блокируют заполнение инструментов: нужен чистый шаблон.

Варианты акта: `Акт прием`, `Акт приема`, `Акт прием-передач`, `Акт приема-передачи`, `Акт прием-передачи`. Если обнаружено несколько вариантов, задайте точный лист в профиле.

Формула возврата по умолчанию выключена. Явное правило профиля разрешает очистку H20/H21 и `L21 = G21-F21`. F21 должна содержать настоящую дату, G21 — получать тип date. Программа не приписывает неизвестным числам смысл даты. Формулу вычисляет Excel.

Противоречия разрешены конфигурацией:

- C22 получает одно поле personal_identifier; конкурирующие ПИН и ИНН не создаются.
- combined пишет только phones в D7; separate — основной в D7, дополнительный в G7. Смешанная схема запрещена валидатором.
- Первая строка инструментов по умолчанию 20 из пользовательской карты; её можно изменить в GUI. Java firstDataRow=19 трактуется как нулевой индекс, исходник не проверен.
- Договорные даты по умолчанию текстовые; тип date выбирается в mapping.
- Пустые поля по умолчанию сохраняют ручные значения Excel. Флажок пропуска пустых можно снять для явной очистки ячейки.
- Формулы заменяются только при разрешении строки профиля либо явном правиле возврата.
- OCR-текст с начальным `=` остаётся строкой. Единственная создаваемая формула — программное правило возврата.
