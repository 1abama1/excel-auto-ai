# CPU-only: выбор движка и контроль точности

19.10.2026. Основной движок — **RapidOCR 3.8.1 + ONNX Runtime CPU 1.23.2**,
модели PP-OCRv5 mobile: детектор, кириллический и английский распознаватели.
PaddleOCR 3.7.0 / PaddlePaddle CPU 3.3.1 / PaddleX 3.7.2 остаётся явным
вариантом в настройках. Автоматического fallback нет.

## Условия измерения

Windows 10 x64, build 19045, Python 3.12.13; Intel Family 6 Model 165,
12 логических процессоров. По два потока inference, один процесс с моделями.
Это рабочий компьютер с другими приложениями; не лабораторно изолированный
benchmark и не измерение на всех офисных CPU. Windows 11 x64 — целевая ОС,
но отдельный прогон на ней не выполнялся.

Одинаковый pipeline и две исходные фотографии FRONT/BACK; разные клиентские
и image ID для каждого нового документа исключают попадание в кеш. Порядок:
Paddle, затем Rapid. Первый запуск включает создание процесса, импорты,
инициализацию моделей и извлечение полей. Медиана двух следующих запусков —
новые документы с уже загруженными моделями. Отдельно измерен повтор тех же
изображений того же клиента с проверкой **нулевого числа новых OCR-вызовов**.
Файловый кеш Windows принудительно не очищался. Время открытия окна не
включено в время OCR. RSS — пиковая сумма родителя и дочернего процесса,
опрос каждые 10 мс; общие страницы могут учитываться дважды.

## Проверка полей

Контрольные значения реального образца прочитаны только в RAM из разрешённого
задания; исходные фотографии, OCR-текст и паспортные значения не копировались
в fixtures, исходники или отчёт. JSON содержит булевы сравнения, статусы,
счётчики, время и память. Синтетические личности вымышлены.

| Контроль | Paddle CPU | Rapid CPU |
|---|---:|---:|
| Реальный образец: фамилия/имя кириллицей и латиницей, отчество | 5/5 | 5/5 |
| Реальный образец: проверенный TD1 и четыре сверки с его полями | пройдены | пройдены |
| Четыре синтетические карты, все 10 критичных полей | 39/40 | 39/40 |
| Синтетические ПИН, номер, рождение, выдача, окончание: 5 × 4 | 20/20 | 20/20 |
| Синтетические формы ФИО, включая отсутствие отчества | 19/20 | 19/20 |
| Длинное имя / имя с дефисом / отсутствие отчества, все поля | 10/10 каждое | 10/10 каждое |
| Короткое имя, все поля | 9/10 | 9/10 |

Единственная ошибка обоих движков — короткое синтетическое кириллическое имя
«ЯН»: модель выдаёт латиноподобные символы. Дополнительные попытки подготовки
этого фрагмента не дали точного результата. Кириллическое поле оставлено
нераспознанным, автоматическое договорное ФИО заблокировано до ручного ввода.
Латинское имя остаётся отдельным полем. Значение не угадывается по словарю или
транслитерации. Этот предел точности не возник из-за выбора более быстрого движка.

У исходного образца движки совпали по всем 11 сравниваемым полям, включая ПИН,
номер и даты. **Совпадение движков и согласованность с MRZ не являются
независимым контрольным эталоном этих чисел.** Полные даты, ведущие нули и
разделение серии/номера независимо проверены на синтетических картах. Орган
выдачи показан в статусах, но не включён в 10 критичных сравнений: приложение
намеренно разделяет `МКК` и код подразделения. Четыре синтетические карты и
один реальный документ не дают оценки точности на генеральной совокупности.

При разногласии печатной латиницы и MRZ сильный FRONT-кандидат остаётся
видимым, конфликт и альтернативы сохраняются. В третьей строке TD1 нет
контрольной цифры имени. Различие только в дефисах/пробелах MRZ не создаёт
ложный конфликт. Кириллица и латиница никогда автоматически не смешиваются
в договорном ФИО.

Для обычного макета с латинским кодом MKK добавлено одно ограниченное чтение
строки, если основной кириллический распознаватель путает ноль с O. Формат не
подставляет цифру: английская модель должна буквально прочитать её, а все уже
прочитанные цифры обязаны совпасть. Готовый код и конфликтующие источники не
перечитываются. Физическая ветка измеренного набора от этого не меняется.

## CPU, фон, кеш и автономность

- Только `CPUExecutionProvider`; проверка отвергает CUDA/DML и другие providers.
  У Paddle CPU `is_compiled_with_cuda=False`. GPU-дистрибутивов в поставке нет.
- Один переиспользуемый процесс; в каждом прогоне backend создан один раз,
  всего три модели. Кириллический распознаватель переиспользуется для ROI;
  английский загружается один раз при первом обращении.
- Нет классификатора угла, разворота строк, unwarping и лишних языковых моделей.
  Геометрический поворот и перспектива сохраняются в общем pipeline.
- Qt QRunnable выполняет работу в фоне; отдельный процесс обеспечивает
  остановку при отмене/timeout. Вкладки, просмотр фото и refresh формы OCR не
  запускают. Новый клиент не получает результаты предыдущего клиента.
- Основной проход по одному на сторону, далее только нужные области/строки MRZ.
  BACK при неясной стороне подтверждается проверенными цифрами TD1, а не
  порядком фотографий. Некорректная MRZ не назначает сторону.
- По умолчанию 2 inference-потока, ORT inter-op 1; OpenCV и численные библиотеки
  ограничены двумя потоками до импорта. Настройка inference допускает 1–8.
- RAM-кеш целых результатов ограничен 16 записями, внутренний кеш worker — 64.
  Ключи учитывают клиента, изображение/байты, настройки, модель, профиль и
  версию алгоритма; результат копируется перед передачей. Очистка удаляет оба.
- Три ONNX-модели поставляются в `models/rapidocr`, проверяются SHA256.
  В runtime нет скачивания; сетевые соединения worker запрещены. В benchmark
  у обоих движков **0 сетевых попыток**, Rapid не импортировал Paddle.

## Воспроизведение

`scripts/benchmark_cpu.py` выполняет сравнение с локальными каталогами моделей;
без `--images` проверяет только синтетические карты. Для закрытого контроля
передаются два разрешённых пути и `--expected-request`, значения не сохраняются.
Итог измерения из готового runtime: `test-artifacts/cpu-comparison-release.json`.
Предыдущий прогон: `test-artifacts/cpu-comparison-final.json`.

Готовая автономная папка: `dist-cpu/DocumentExcel`; запуск — `DocumentExcel.cmd`
или корневой `Launch.cmd`. Переносится **вся папка**, установка Python/CUDA не
нужна. Необходим VC++ Redistributable 2015–2022 x64. Установка из исходников:
`scripts/setup_cpu.ps1` (Python 3.12); сеть нужна только установщику. Версии
поставки сохранены в `requirements-locked.txt`, SHA исходников — в `build.json`.

Проверки релиза и интерфейса приведены в начале `TEST_REPORT.md`.

Финальная регрессия: **480 passed**, ещё **3 passed** реальных Qt/CPU-теста.
Оба синтетических сценария OCR → XLSX с двумя фотографиями и запуск через
поставочный `.cmd` пройдены из `C:/Windows`. Проверены SHA всех 57 файлов
приложения и обоих наборов моделей. Выполнена самопроверка кода: стороны/TD1,
разделение алфавитов, сохранение ручного ввода, отмена/ошибка уточнения, изоляция
и очистка кеша, источники и геометрия. Отдельный агент для review не привлекался.
